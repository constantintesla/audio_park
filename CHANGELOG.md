# Changelog

## [Unreleased]

### Добавлено
- **Блок «Задания и записи»** в результатах (и в детальном отчете на «Обзоре»): у каждого задания обследования - что нужно было сказать, записи всех попыток с плеером и кнопкой «Скачать», измерение попытки и отметка засчитанной. Кнопка «Скачать архив прогона» отдает ZIP: вся запись, калибровка, записи заданий по отдельности и `results.json`.
- ✅ **Нормализация громкости при загрузке**: каждая запись приводится к -23 LUFS (ITU-R BS.1770, с гейтированием пауз), чтобы разные микрофоны и усиление давали одинаковый уровень. В `audio_summary` добавлены `input_lufs` и `normalization_gain_db`.

### Исправлено
- Таблица на «Обзоре» и кнопка «Графики» в «Результатах» открывали не тот анализ: брался номер строки в отсортированном списке, а не номер записи.
- **Shimmer** считался по контуру интенсивности в дБ (кадры 10 мс) и выходил в 15–30 раз меньше настоящего: 0.2% вместо 3.4%. Теперь это стандартный Praat «Get shimmer (local)» по меткам периодов, порог охриплости 6% снова срабатывает.
- **Jitter**: Praat вызывался с неверными аргументами (вместо времени от/до передавались границы периода), получал NaN, и всегда срабатывал запасной расчет по треку F0, занижавший jitter на 25–30%. Теперь jitter - Praat «Get jitter (local)», как в нормах и в формуле DSI.
- **Счет слогов** (темп чтения, фразы, серии слогов): шипящие и свистящие давали отдельный пик громкости, «ша ша ша са са са…» считалось вдвое быстрее. Теперь ядро слога - пик в полосе гласных 300–2500 Гц, в котором есть тон (de Jong & Wempe 2009).
- **Паузы в шумной записи**: при шуме ближе 25 дБ к голосу паузы не находились, а темп чтения занижался на четверть; MPT удлинялся на запас по краям попытки. Порог тишины теперь не ниже шума комнаты + 6 дБ.

### Изменено
- ✅ **Гипофония оценивается независимо от устройства**: вместо абсолютного RMS используются наклон спектра (`spectral_tilt_db`, энергия 1-3.5 кГц относительно 0.3-1 кГц) и затухание громкости к концу записи (`loudness_decay_db`). Пороги предварительные, требуют калибровки на реальных записях.
- Запасной путь без parselmouth теперь тоже считает признаки амплитуды (раньше гипофония в нем всегда получала 3).

### Удалено
- Telegram бот (`bot.py`, `start_bot.py`), зависимость `aiogram`, переменная `TELEGRAM_BOT_TOKEN` и сервис `bot` в docker-compose. Остался только веб-интерфейс.

## [1.1.0] - 2025-01-19

### Изменено
- ✅ **Убраны капы и фолбеки из параметров** - теперь возвращаются настоящие значения без искусственных ограничений:
  - HNR: убраны капы на 8.0 дБ (минимум) и 25.0 дБ (максимум)
  - Jitter: убраны капы на 5.0% (максимум) и 0.01% (минимум)
  - Shimmer: убран кап на 50.0% (максимум)
  - Все параметры теперь отражают реальные результаты расчета

### Добавлено
- ✅ **Функция пересчета всех результатов** - кнопка в веб-интерфейсе для пересчета всех сохраненных результатов с обновленными алгоритмами
- ✅ **Реорганизован веб-интерфейс**:
  - Главная страница (`/`): сводная таблица результатов + отображение одного результата при клике
  - Страница списка результатов (`/results`): полный список всех результатов в виде карточек
  - Страница визуализации (`/visualization?index=X`): автоматический выбор записи по индексу из URL
- ✅ Автоматическая прокрутка и фокус на отчет при клике на строку таблицы
- ✅ Кнопка визуализации в карточках результатов для прямого перехода

### Улучшено
- Более точные результаты анализа за счет использования реальных значений параметров
- Улучшенная навигация между страницами
- Оптимизированная структура интерфейса

## [1.0.0] - 2024

### Добавлено
- ✅ Telegram бот для анализа голоса через голосовые сообщения
- ✅ Веб-интерфейс для просмотра результатов всех пользователей
- ✅ DSI (Dysphonia Severity Index) - расчет и интерпретация
- ✅ API сервер с экспортом результатов (CSV, JSON, HTML)
- ✅ Полный отчет в Telegram после обработки голосового сообщения
- ✅ Docker контейнеризация для простого развертывания
- ✅ Автоматическое сохранение результатов в `results.json`
- ✅ Статистика: общее количество анализов, пользователей, анализов за неделю
- ✅ Страница визуализации параметров с графиками и аудио

### Функциональность
- Извлечение акустических признаков (Jitter, Shimmer, HNR, F0, MPT и др.)
- Анализ симптомов болезни Паркинсона (оценка 0-3)
- Оценка риска ПД на основе пороговых значений
- Детальный текстовый отчет с рекомендациями
- Сохранение сырых данных (аудиофайлы, waveform, спектрограммы)

### Технические детали
- Python 3.11+
- Flask API сервер
- Aiogram для Telegram бота
- Parselmouth для анализа голоса
- Librosa для обработки аудио
- Docker и docker-compose для контейнеризации
