# Анализатор речи для выявления симптомов болезни Паркинсона

Система анализа речи, специализирующаяся на обнаружении симптомов болезни Паркинсона на основе акустических характеристик голоса. Основана на исследованиях:

- **Little et al. 2004**: 104 акустических признака
- **Daoudi 2022**: Monopitch и phonatory instability
- **NIH 2025**: 12 вокальных биомаркеров для оценки прогрессии
- **Российские ИИ-инструменты скрининга (2023-2025)**

## Вход и разделы приложения

Все исследования доступны после входа. Учётки приложения независимы от исходной системы.

- `expert`: обследование разных пациентов, просмотр и экспорт своих исследований.
- `moderator` и `admin`: дополнительно все исследования, пересчёт и создание учёток.
- `/` — новое обследование; пациент выбирается из списка врача или создаётся автоматически. ID исследования `AP-<дата>-<UUID>` выдаётся сервером.
- `/results` — свои исследования; `/all-results` — все исследования для старших ролей.
- `/visualization?study=<ID>` — отчёт, графики и аудио конкретного исследования.
- `/users` — создание учёток (логин/email, пароль, роль).

Первичный импорт PostgreSQL-выгрузки и создание дополнительного администратора:

```bash
python scripts/manage_accounts.py /private/path/accounts.txt --admin tesla
# Пароль нового администратора вводится в скрытом приглашении.
```

Повторный импорт пропускает существующие учётки, сохраняя изменённые пароли.
Импорт поддерживает хэши `scrypt:32768:8:1` из текстовой таблицы `id | email | role | password`.
База учёток и ключ сессий находятся в `auth_data/` (в Docker — в отдельном постоянном томе).
Они исключены из Git и образа. Для HTTPS включите `SESSION_COOKIE_SECURE=true`; для локального HTTP — `false`.

У каждого врача своя автоматическая нумерация (`Пациент 1`, `Пациент 2`, …), поэтому одинаковые
локальные номера у разных врачей не пересекаются. Связи хранятся по случайному внутреннему UUID,
который интерфейс не показывает. `GET/POST /api/patients` возвращает список и создаёт следующего
пациента текущего врача. Старые строковые `patient_id` автоматически получают UUID при первом
открытии списка пациентов.

`POST /api/analyze` принимает `patient_uuid` из выбранной карточки, сохраняет результат один раз и назначает владельца по сессии.
Поле `patient_id` временно поддерживается для старых интеграций.
Перед POST-запросами API получите `/api/auth/csrf`, затем передавайте `X-CSRF-Token` и cookie сессии.
После входа токен обновляется. `GET /api/results` и экспорты возвращают свои данные;
`?scope=all` разрешает старшим ролям получить все. Дополнительные фильтры: `q`, `patient_id`, `owner_id`, `date_from`, `date_to`.
Старый `POST /api/results` отключён. Аудио и графики проверяют доступ к исследованию.
Общедоступный `/healthz` возвращает только состояние сервиса.

## DSI (Dysphonia Severity Index)

Система рассчитывает DSI по формуле:
```
DSI = 0.13 × MPT + 0.0053 × F0-High - 0.26 × I-Low - 1.18 × Jitter(%) + 12.4
```

**Интерпретация DSI:**
- **+2…+5**: Нормальный голос
- **0…+2**: Легкая дисфония
- **-2…0**: Умеренная дисфония (PD 1-2)
- **<-2**: Тяжелая дисфония (PD 3-5)

**Параметры DSI:**
| Параметр | Норма | При Паркинсоне |
|----------|-------|----------------|
| MPT (сек) | >15-20 | <10 (слабость дыхания) |
| F0-High (Гц) | >400-500 | <300 (monopitch) |
| I-Low (дБ) | <45 | >55 (тихий голос) |
| Jitter (%) | <1 | >1.5-2 (дрожь) |

DSI коррелирует с Voice Handicap Index и идеален для мониторинга терапии (LSVT LOUD).

## Пороговые значения

Система использует следующие пороговые значения на основе исследований:

| Признак | Порог | Референс (норма) | Интерпретация |
|---------|-------|------------------|---------------|
| Jitter | >1.1% | 0.0-1.0% | Нестабильность голосовых связок |
| Shimmer | >7.5% | 2.0-4.0% | Вариация амплитуды |
| HNR | <13dB | 20-25 дБ | Breathy voice |
| F0 SD | <50Hz | 10-50 Гц | Monopitch |
| Скорость речи | <3 сл/сек | 4.5-7.0 сл/сек | Медленная речь |
| Паузы | >30% | 0-30% | Проблемы с артикуляцией |

**Важно:** Все параметры возвращаются с реальными значениями без искусственных ограничений. При ≥3 признаках, превышающих пороги: **89% точность** (Daoudi 2022).

## Хранение результатов

Все результаты анализа сохраняются в файле **`results.json`** в корне проекта. Каждая запись содержит:
- Информацию о пользователе (username, user ID, дата/время)
- Все акустические признаки (реальные значения без капов)
- DSI (Dysphonia Severity Index) с параметрами
- Оценку симптомов (0-3) и оценку риска ПД
- Полный текстовый отчет
- Ссылки на сырые данные (аудиофайлы, waveform, спектрограммы)

Сырые данные сохраняются в директории `results/{result_id}/` для каждого анализа.

## Запись с разных устройств

Чтобы результаты с разных телефонов были сравнимы, приложение передает в
`POST /api/analyze` поле `device_info` — JSON с метаданными записи:

```json
{
  "device_id": "стабильный id устройства в приложении",
  "device_model": "Pixel 7",
  "os": "Android 14",
  "app_version": "1.0.0",
  "mic_mode": "unprocessed",
  "input_format": "wav",
  "sample_rate": 48000,
  "noise_floor_dbfs": -72.5,
  "spl_offset_db": 94.0,
  "task": "speech"
}
```

`task` — что записано:
- `speech` — обычная речь (фраза, чтение). По ней оцениваются интонация, громкость,
  темп и паузы. Jitter, shimmer и HNR по речи не оцениваются: их нормы даны для
  протяжной гласной, а в речи они завышаются, и здоровый голос выглядит «охрипшим».
- `vowel` — протяжная гласная «а-а-а». По ней оценивается охриплость (jitter, shimmer, HNR);
  интонация и темп не оцениваются.
- `dsi` — запись с заданиями DSI: самая долгая гласная «а» на одном выдохе (MPT),
  скольжение голосом до самой высокой ноты (F0-High) и самый тихий голос (I-Low).
  Только для такой записи и только при заданном `spl_offset_db` считается DSI.
  Упражнения идут в одной записи друг за другом, а их границы приложение передает
  в `dsi_segments`: `[{"task": "mpt" | "glide" | "soft" | "vowel", "start_sec": 1.2, "end_sec": 14.8}, ...]`.
  MPT берется по лучшей попытке `mpt`, F0-High по самой высокой ноте в `glide`,
  I-Low по самой тихой попытке `soft`, jitter и охриплость по спокойной гласной `vowel`.
  Без калибровки (`spl_offset_db`) I-Low оценивается по обычной громкости самого человека:
  спокойная «а» на 30 см считается равной ~70 дБ SPL, и самый тихий голос пересчитывается
  относительно нее. Тогда DSI помечается как оценка (`approximate`, `uncertainty` ≈ ±1.3).
  Когда на одной модели устройства (`device_model` + `mic_mode`) пройдут тест хотя бы
  5 разных устройств, сервер берет поправку модели по их средней обычной громкости
  (`device_model_stats.py`): так точнее (≈ ±0.8), и громкий или тихий от природы
  человек не сдвигает результат.

Калибровочный тестовый звук играет динамик того же устройства, поэтому абсолютную
чувствительность микрофона из него не получить. Но при максимальной громкости его
уровень у одной модели почти постоянен: если запись отличается от обычного для
модели больше чем на 6 дБ (`calibration_check`), в отчете появляется просьба проверить
громкость и не закрыт ли микрофон.
- `speech_protocol` — речевые задания (документ «Задания по голосу»), одной записью друг за другом.
  Границы заданий приложение передает в `protocol_segments` в том же формате, что `dsi_segments`.
  Задания (`task`): `mpt` — «а» на обычной громкости так долго и ровно, как получится (лучшая попытка);
  `reading` — чтение текста «Буря на реке»; слоги `syl_sibilant` (са-ша-за-жа), `syl_sonorant`
  (ла-ра-ра-ла), `syl_voicing` (па-ба-па, та-да-та, ка-га-ка), `syl_palatal` (са-ся, ла-ля, та-тя),
  `syl_airflow` (ша ша ша, са са са, са-сы-су-се); фразы `phrase_slow`, `phrase_fast`, `phrase_normal`
  (одна попытка — одна фраза); `intonation` — вопрос с ударением на выделенном слове и ответ.
  Интонация, громкость и темп в общем отчете оцениваются по чтению текста. Показатели по заданиям
  лежат в блоке `speech_protocol` ответа (`speech_protocol.py`): MPT, темп и паузы чтения, разброс
  тона в полутонах, темп и неровность слогов, темп фраз и во сколько раз «быстро» быстрее «медленно»,
  размах тона в вопросах. DSI по этой записи не считается.
- `exam` — обследование: задания DSI и речевые задания в одной записи. Приложение передает
  и `dsi_segments`, и `protocol_segments` (долгая «а» `mpt` входит в оба списка). Считаются DSI
  и показатели речевых заданий; охриплость (jitter, shimmer, HNR, CPPS) оценивается по спокойной
  «а» `vowel`, интонация, громкость и темп — по чтению текста. На веб-странице это кнопка «Обследование».

Если `task` не передан, тип определяется сам: протяжная гласная — это один длинный
непрерывный озвонченный участок, в обычной речи тон прерывается. DSI по обычной
записи не считается (`dsi.status = "not_applicable"`, причина в `dsi.reason`):
из нее нельзя измерить MPT, F0-High и I-Low, и формула дает около −11 даже для
здорового голоса. DSI оценивает качество голоса, а не болезнь Паркинсона.

`noise_floor_dbfs` — уровень шума, измеренный по 1–2 с тишины перед записью.
Без него шум оценивается по самым тихим кадрам записи.
`spl_offset_db` — поправка из калибровки устройства для перевода dBFS в dB SPL. Неизвестные поля
отбрасываются.

В ответе появляются блоки:
- `quality` — вердикт `ok` / `warning` / `reject`, проблемы записи и список
  признаков, которым нельзя доверять (`unreliable_features`). При `reject`
  рекомендация заменяется просьбой перезаписать голос.
- `features.cpps_db` — CPPS, менее зависимая от микрофона альтернатива HNR.
- `baseline` — отклонения от медианы прошлых записей этого же пользователя
  на этом же устройстве (нужно не меньше 3 пригодных записей, до этого
  статус `collecting`). Признаки с `robust_z` по модулю больше 2.5
  попадают в `flagged_features`.

## Пересчет результатов

Если вы обновили алгоритмы извлечения признаков, можно пересчитать все сохраненные результаты:

1. Откройте веб-интерфейс на главной странице
2. Нажмите кнопку "Пересчитать все результаты"
3. Подтвердите действие
4. Дождитесь завершения (прогресс отображается в реальном времени)

## Важные замечания

- ⚠️ **Система предназначена для исследовательских целей и не заменяет медицинскую диагностику**
