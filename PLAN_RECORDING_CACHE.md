# План: сохранение обследований и повторная отправка

## Цель

Сохранять данные до отправки на сервер, чтобы сбой сети или перезагрузка страницы не приводили к потере обследования и его можно было отправить повторно.

## Текущее состояние

Реализовано 13 ноября 2026 года. Завершённые записи и незавершённые обследования
хранятся в IndexedDB отдельно для каждого владельца. Запись сохраняется фрагментами
примерно каждые две секунды; после перезагрузки доступны прослушивание, продолжение,
скачивание и отправка. Повторные запросы сериализуются на сервере через SQLite,
а результат определяется по владельцу, постоянному идентификатору и SHA-256 запроса.

Локальный формат v1 содержит владельца, пациента, время создания и обновления,
состояние, аудио и калибровку, параметры устройства, границы выбранных попыток,
контрольную сумму отправляемого содержимого и идентификатор серверного результата.
Черновик дополнительно хранит PCM-фрагменты, текущий шаг, число завершённых попыток,
прерванную попытку и состояние перезаписи. Ревизия защищает черновик от записи устаревшей
вкладкой. Метаданные и новые аудиофрагменты фиксируются одной транзакцией;
при завершении они атомарно заменяются готовым комплектом WAV и калибровки.

Все пять состояний реализованы. Прерванное состояние «Отправляется» при открытии
страницы переводится в «Ошибка» с предложением проверить результат или повторить.
Активная отправка другой вкладки защищена Web Locks, где они доступны; серверная
защита от дублей действует независимо от поддержки Web Locks.

При ошибках хранения запись приостанавливается, отправка блокируется, остаётся
скачивание из памяти и повторное сохранение. При истечении сессии страница не
перенаправляется со сбросом записи; повторный вход в той же учётной записи в другой
вкладке позволяет продолжить отправку. Смена владельца в другой вкладке блокирует
серверные запросы старой страницы. Выход сохраняет локальные копии; интерфейс
предупреждает об этом и предоставляет ручное удаление всех копий текущего владельца.

## План реализации

1. Определить общую структуру локального обследования: постоянный идентификатор, версия формата, владелец, пациент, аудио, калибровка, параметры записи, границы заданий, попытки и выбранные записи.
2. Добавить хранение в IndexedDB. Сохранять данные по мере записи и проверять сохранение полного комплекта перед отправкой. Конкретный способ промежуточного сохранения согласовать с текущим аудиорекордером.
3. Добавить состояния: «Записывается», «Сохранено», «Отправляется», «Ошибка», «Отправлено». После перезапуска незавершённую отправку переводить в состояние, допускающее проверку результата и повтор.
4. Добавить список «Неотправленные обследования»: восстановление, прослушивание, повторная отправка, скачивание резервной копии и удаление.
5. Обеспечить повторную отправку без дубликатов на сервере. Передавать постоянный идентификатор запроса; сервер должен учитывать текущего владельца, распознавать повторный запрос, возвращать уже сохранённый результат и предотвращать параллельное создание дублей. Изменённые данные не должны незаметно использовать тот же идентификатор.
6. Сохранять локальную копию при любых ошибках отправки. Отмечать обследование отправленным только после подтверждения сервера. Удалять данные вручную либо по явно заданному правилу хранения.
7. Обрабатывать нехватку места, недоступность хранилища и истечение сессии. Если сохранение не удалось, сообщать об этом и предлагать скачать копию; не продолжать отправку молча без сохранения.
8. Изолировать локальные обследования по учётным записям. Предусмотреть поведение при выходе и работе на общем компьютере.

## Основные места изменений

- `web/index.html` — жизненный цикл записи, восстановление и отправка.
- `web/assets/` — отдельные модули локального хранилища и очереди обследований.
- `web/assets/recording-cache.js` — промежуточные PCM-сохранения, восстановление и продолжение.
- `web/assets/exam-files.js` — IndexedDB v2 с миграцией прежних копий, ZIP и общая контрольная сумма запроса.
- `web/assets/exam-file-ui.js` — список локальных копий, состояния, ошибки хранения и отправка.
- `app/api.py` и серверное хранилище — обработка повторных запросов и фиксация результата.
- `scripts/test_recorder.cjs` и серверные проверки — сценарии восстановления и отсутствие дубликатов.

## Проверки и критерии готовности

- [x] Обследование восстанавливается после перезагрузки страницы.
- [x] После обрыва сети доступны прослушивание и повторная отправка.
- [x] Потеря ответа после успешного анализа не приводит к второму исследованию.
- [x] Два одновременных первых запроса одного обследования не создают дубликаты.
- [x] Незавершённая запись восстанавливается в пределах последнего сохранённого фрагмента с понятным обозначением неполноты.
- [x] Ошибка локального сохранения отображается пользователю до отправки.
- [x] Данные одной учётной записи не показываются другой.

## Ограничение

IndexedDB не заменяет резервную копию: браузер или пользователь могут очистить хранилище. Независимая копия на диске предусмотрена в `PLAN_FILE_IMPORT_EXPORT.md`.

При аварийном завершении могут отсутствовать последние ещё не зафиксированные
фрагменты (обычно до двух секунд). Незавершённая попытка повторяется. Продолжение
записи требует того же микрофона и частоты дискретизации; если была прервана
калибровка, она запускается заново в новом обследовании, а старая копия остаётся
доступной. ZIP сохраняет неполные данные с явным признаком `incomplete`; для
восстановления текущего шага рекордера используется браузерный кэш.
